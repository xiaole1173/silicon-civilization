### 一、项目主体与摘要（What）
我们做了一个多智能体社会实验基座：把多个模型放进同一个会话，让它们在共享世界里按规则对话、协作、博弈，并把「条件 × 重复 × 指标 × 成本」全部装置化。具体玩法以插件接入，目前有四个，未来会扩增更多：
| 插件 | 场景 | 状态 |
|---|---|---|
| commons | 公地困境（可再生共享资源） | 完善框架阶段，已完成真模型实验（120 局） |
| rules_horror | 规则怪谈（条文可程序化检查） | 完善框架阶段，已完成真模型实验（6 局） |
| werewolf | 狼人杀（12/9 人，官方规则对齐） | 插件完整，真模型批次待额度 |
| discussion | 圆桌讨论（基座自检） | 已完成（示例） |

核心研究问题：
- RQ1：在共享可再生资源场景中，资源再生率 ρ（稀缺程度）如何影响合作率与资源崩溃概率？
- RQ2：沟通、合约与第三方调解能否缓解稀缺导致的过度取用？
- RQ3：给 Agent 注入角色卡，是否会改变其发言与决策行为？
已完成的关键事实：真模型 126 局（公地 120 + 怪谈 6），累计 2.54M token，估算成本 $1.37，0 次调用失败。
### 二、项目目的与意义（Why）
- 研究意义：把"一群 AI 聊天"变成受控实验——有假设、有对照、有重复、有失败复盘，
并能回答"这个结果说明什么、不说明什么"。
- 课程意义：满足"聚焦问题 + 受控实验 + 重复试验 + 发现 + 可见性"五项要求；
实验装置（批次/清单/指标/报告/回放）可直接复用。
- 产品意义：角色卡模板、插件协议、日志格式、回放台，都是可复用的资产。
- 社会意义：用公地的过度取用、怪谈的规则遵循、狼人杀的信任与投票，直观呈现合作、公平、信任与集体生存。

### 四、解决方案与实验设计
#### 4.1 基座架构（原"Harness"）
没有使用第三方 Harness：基座是自研的零依赖 Python 实现（http.server + urllib），
模型通过 HTTP 直连（支持 chat_completions / responses / anthropic_messages 三种协议）。
| 层 | 作用 | 产物 |
|---|---|---|
| 会话/频道/回合 | 公共、私密、观察者三类频道；回合卡组织对局节奏 | 实时 SSE 流 |
| 裁判（GM） | 只播报公共状态：轮次、资源、结算、规则触发；不参与博弈 | referee 消息 |
| 上下文装配 | 稳定 system + 只追加历史 + 事实卡 + 本轮指令；超预算裁剪并留痕 | meta.context |
| 校验与重试 | 不符合格式的回答带着原因重说（默认 1 次） | validation_failed 事件 |
| 事件日志 | 每个动作落 JSONL，可回放、可离线分析 | runs/sessions/<id>.jsonl |
| 插件协议 | system_text / facts / validate / setup / run / metrics / outcome | 一个场景一个目录 |

#### 4.2 角色卡（已落地，非设想）
5 张卡在 cards/*.yaml，字段：role / goal / public_identity / private_info / risk_appetite / style / trust_initial / forbidden / win_condition。
- 每张卡有内容哈希版本号（card-xxxxxxxx），注入 system 稳定块，并写入每条消息的 meta.role_card_version；
- 开关 persona: on|off 可整组关闭角色卡（用于 RQ3 的对照）；
- 卡片只描述实验设定，不是对真人的人格判断。
#### 4.3 GM 与收敛机制（据实修正）
已实现：
- 回合制推进 + 裁判播报 + 确定性结算（谁取了什么，由代码算，不由模型声称）；
- 狼人杀内的投票与 PK（含警长 1.5 票、弃权、平票 PK）；
- 公地内的议约（提议上限 → 附议 → 生效 → 违约检测 → 惩罚）。
未实现（列为二期）：跨场景通用的"3 轮未形成方案自动强制投票"协议。
原因：与当前 RQ 无关，且公地场景不存在"方案共识"这一动作；强行加入会污染结算。
#### 4.4 三个场景（据实描述）
| 场景 | 核心冲突 | 每轮流程 | 关键指标 |
|---|---|---|---|
| 公地困境（commons） | 多取 1 捆自己全得、草场损失 6 户分摊 | 声明 → 议约 → 取用 → 结算 | 合作率、基尼、枯竭轮、崩溃、违约率 |
| 规则怪谈（rules_horror） | 条文可被程序检查，违规即被带走 | 逐条发言 / 请管理员解释 / 沉默 | 违规数、违规率、求助次数、存活 |
| 狼人杀（werewolf） | 隐藏身份、信任、误杀 | 夜间行动 → 白天发言 → 投票 | 天数、出局数、调用失败数 |

公地困境的激励结构（v1 遗漏的关键）：
提示词必须写明"收益私有、成本分摊"——这是 Hardin 牧羊人设定的核心：
- 你割到的草料全部是你的收成；
- 你多割 1 捆，草场少 1 捆，损失由 6 户平摊，你只承担 1/6；
- 因此多割 1 捆净得 1 − 1/6 ≈ 0.83 捆。
只写"草场归零所有人都输"会退化成道德题：我们实测过，那样 120 局零崩溃。
实现上由 incentive: classic|moral 切换，moral 保留为对照条件。
#### 4.5 条件矩阵（把 C0–C3 映射到实际开关）
v1 的"C0 无角色卡/无 GM 结构"字面不可行——GM 就是裁判与结算，删掉实验不成立。
改为"无状态广播"：Agent 只看到自己的账本。四条件与开关一一对应：
| 条件 | 原名 | 实际开关 | 含义 |
|---|---|---|---|
| C0 | 基线（无角色卡/无结构） | persona=off + info_visibility=self | 无角色卡、看不到别人取用 |
| C1 | 角色卡 + GM 广播 | persona=on + info_visibility=full | 有角色卡、公开账本 |
| C2 | C1 + 公开日志 | C1 + show_reputation=on | 追加声誉可见 |
| C3 | C2 + 协商规则 | C2 + contracts=on + mediation=on | 追加合约与违约惩罚 |

实际执行情况：公地主实验用的是 ρ（3 档）× 沟通（开/关）× 20 seeds，共 120 局；
C0–C3 的完整四条件矩阵尚未跑满（需额度），已写进"待办"。
#### 4.6 指标口径
所有统计由 base/metrics.py 统一计算，插件只声明自己特有的指标。
| 指标 | 定义 | 适用场景 |
|---|---|---|
| cooperation_rate | 取用量 ≤ 可持续份额（cap×ρ/人数）的比例 | 公地 |
| gini | 各户累计取用的基尼系数 | 公地 |
| depletion_round / collapse | 存量首次跌破 10% 的轮次 / 是否崩溃 | 公地 |
| contract_breaches / breach_rate | 合约违约数与占比 | 公地（开启合约时） |
| violations / violation_rate | 违规数与违规率 | 规则怪谈 |
| help_requests | 主动请求澄清规则的次数 | 规则怪谈 |
| tokens_* / cost_usd | token 用量与估算成本 | 全部 |

权力结构指标（新增，离线计算，不改插件）：base/power.py 只读 JSONL，输出
proposals（提议数）、adoption_rate（被 ≥2 人附议的比例）、ignored_agents（发言但从未被他人提及）、
speak_concentration（发言占比最大值）、decision_concentration（决定占比最大值）、
voice_vs_power_gap（"说话最多"与"决定最多"的落差）。
适用边界：这些指标只有在"有商议"的场景才有意义（狼人杀、圆桌讨论）。
公地场景是各自独立取用、没有商议，实测 proposals=0——这一条要如实写进结论，而不是拿 0 当"无人提议"。
### 五、阶段性结果
说明：本章是阶段性结果，用来证明装置可用、指标可算、成本可控；方案本身不依赖这些数字成立。这些对局由基座开发者执行，属于框架稳定性测试，不作为场景结论；场景结论由各场景 owner 产出。
#### 5.1 公地困境：120 局（N=20/条件）
模型组：gpt-6-luna、gpt-5.6-terra、gpt-6.1-sol、gpt-6-sol、gpt-6-astra、claude-haiku-5-5；每局 6 轮、6 座位。
| 条件 | n | 合作率（均值±95%CI） | 基尼 | 崩溃 |
|---|---|---|---|---|
| ρ=0.02 沟通关 | 20 | 0.954 ± 0.022 | 0.077 | 0 |
| ρ=0.02 沟通开 | 20 | 0.981 ± 0.021 | 0.073 | 0 |
| ρ=0.05 沟通关 | 20 | 0.861 ± 0.020 | 0.027 | 0 |
| ρ=0.05 沟通开 | 20 | 0.989 ± 0.016 | 0.007 | 0 |
| ρ=0.10 沟通关 | 20 | 0.915 ± 0.027 | 0.031 | 0 |
| ρ=0.10 沟通开 | 20 | 0.997 ± 0.004 | 0.016 | 0 |

三条结论：
1. 沟通稳定有益：三档 ρ 下"沟通开"都高于"沟通关"，差值 0.03–0.13，置信区间不重叠；
1. 稀缺与合作不是单调关系：ρ=0.05 的"沉默"条件合作率最低（0.861），ρ=0.02 反而较高（0.954）；
1. 稀缺加剧不均：ρ=0.02 的基尼（0.073–0.077）明显高于 ρ≥0.05（0.007–0.031）。
1. 核心：只写"草场归零所有人都输"会退化成道德题：我们实测过，那样 120 局零崩溃。
因此 RQ1 的"崩溃概率"这一支没有被检验到：只能说"在本设置下崩溃概率 < 约 2.5%（0/120 的置信上界）"，不能说"稀缺不影响崩溃"。
成本：2,544,874 token，约 $1.37（按 0.5 / 1.5 USD 每百万 token 估算）。
#### 5.2 规则怪谈：6 局
三条可程序检查的规则（禁词"血"、单轮 ≤40 字、必须发言），违规 3 次出局，每局 5 轮。
| 条件 | n | 违规率 | 求助次数 | 存活 |
|---|---|---|---|---|
| 沟通开 | 3 | 0.000 | 0 | 6/6 |
| 沟通关 | 3 | 0.000 | 0 | 6/6 |

结论：条文一旦明示且可检查，模型遵守得很好（零违规、零淘汰）；同时一次都没主动请求解释（求助 0）。
一条方法论教训（写进报告会更可信）：第一版跑出"违规率 0.394、平均存活 2.8"，看着很有戏，其实是假的——模型输出 {"action":"speak","content":"..."}，而校验器只认 kind/text，全部被拒后记成"沉默"，反而触发了"必须发言"。修好键名别名后归零。先修仪器，再看数据。
#### 5.3 狼人杀：插件完整，真模型批次待跑
已实现并单元测试：警长竞选（上警/竞选发言/退水/警下投票/PK/警徽移交）、自爆（含吞警徽）、狼王/白狼王带人、遗言、否决门槛、屠边判定；12 人标准场与四套预设。
尚未跑真模型批量（受额度限制），当前只有本地 mock 对局用于验证规则。

所有场景的插件实现由梁俊灏（插件总舵）统一评审后合入；他只是评审与规范，不承担某个场景的跑批与报告。
规则一：每个场景至少有一名 owner，owner 对该场景的配置、跑批与报告负责；同时至少配一名职能支持，避免单点。

规则三：一个场景若长期没有 owner，底座只保证它能跑（冒烟级），不产出场景结论——这是有意的取舍，避免无人负责却挂着结论。
新增场景的四步（不改基座、不改分工表）：

### 九、token 预算
实测结构：token 的大头是「开发对话」，不是「实验运行」。本轮基座开发对话已消耗约 627M token，而 126 局实验仅 2.56M token，相差约 245 倍。因此预算应按「开发为主、实验为辅」估算，而不是按「每次调用 10 万 token」推算。
| 预算项 | 依据 | token | 占比 |
|---|---|---|---|
| 底座开发与调试 | 本轮实测：基座 + 4 插件 + 实验装置 + 前端 + 文档 | 630M | 52% |
| 场景适配（3 名 owner） | 每人约 60M：写配置、调条文、跑小批、写报告 | 180M | 15% |
| 实验运行 | 公地约 21k/局；狼人杀约 500k/局；合计约 240 局 | 60M | 5% |
| 分析与报告 | 统计、图表、LLM judge 抽样、文档 | 40M | 3% |
| 重跑与失败重试 | 解析容错、额度中断、条件变更 | 80M | 7% |
| 不可预见备用 | 约 20% | 210M | 18% |
| 合计建议申请 | 含约 10% 余量 | 1.2B | 100% |

上表按上述实测结构重算；v1 的 20 亿来自错误的单次调用假设，已废弃。
### 十、风险、伦理与局限
| 风险 | 现状 | 应对 |
|---|---|---|
| 天花板效应 | 公地 120 局零崩溃 | 报告只声称"未观察到崩溃（上界约 2.5%）"；用压力档演示机制；下一步改动机结构（收益私有幅度、可见他人多取、资源不可再生） |

| 额度与限流 | 网关 403（额度耗尽）、并发会触发 429 | 已做并发闸门（默认串行，>1 需显式授权）与批次"额度中止" |
| 模型差异 | 固定 6 个模型 | 报告模型差异而非假装公平；换模型组可复跑 |
| 过度外推 | — | 结论只说明本设置下的行为倾向，不外推为人类定律 |
| 隐私 | 角色卡由团队自拟 | 不使用真实聊天记录；卡片是实验设定，不是人格判断 |
| GM 偏置 | GM 只执行公开规则、不参与博弈 | 保留 GM 版本与广播记录 |

### 十一、附录
#### 附录 A：日志字段（实际）
JSONL 事件流（每行一个事件）：
- meta：id / title / scenario / config / agents[]
- session：running / ended（含 winner）
- round_start / round_end：回合 id、标题、副标题、结论摘要
- message_start / message_end：id、channel、sender、kind、text、thinking、meta
- delta：流式增量（回放时跳过）
- turn / state / world / validation_failed / context_trim
每条消息的 meta 含：model、label、attempts、rejections[]、latency_ms、usage、ok、
temperature、max_tokens、harness、role_card_version、round、action。
index.csv（逐局汇总，39 列）含：run_id / condition / seed / state / winner / o_* / m_* / tokens_* / cost_usd / duration_s。
#### 附录 B：结论模板
在本实验条件下，______（操纵）使______（指标）从______变为______（含 95%CI）；证据为______（批次 id 与样本量）。
这说明______；但不说明______（例如"稀缺会/不会导致崩溃"在本次未触发），原因是______。
下一步将通过______（新条件/新场景/换模型组）验证。
